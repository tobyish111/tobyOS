# Chromium bring-up — M0: the first gap list (Track B / Linux, headless)

**Milestone M0 deliverable: the gap list.** Per the agent prompt
(`docs/chromium-bringup-agent-prompt.md`) and the instrument-first
methodology, M0 is *"produce the first gap list and stop — that single
artifact tells us how big this really is."* This document is that artifact.

Target binary: **chrome-headless-shell 151.0.7922.34** (linux64), the
standalone headless Chromium from Google's open Chrome-for-Testing channel —
the real, unmodified V8 + Blink engine, bundling SwiftShader (software
GL/Vulkan) so no GPU driver is needed. Fetched by
`programs/chromium/build.sh`; run by `logs/chromium-m0.sh`.

---

## TL;DR — how big is this, really?

Much smaller than the roadmap (`docs/browser-chromium-v8-roadmap.md`) feared,
because **the single most-feared wall is already gone**: glibc dynamic linking
works on tobyOS today. Prior Track B milestones (see the `linux-abi-compat-b1`
memory: B25–B27 + realtool/realtools/realbash/realpython/realcc) already run
**real, unmodified glibc-dynamic third-party programs** — GNU Binutils
(readelf/objdump/nm), **GNU bash 5.2**, **CPython 3.10**, **TinyCC** — via the
real `ld-linux-x86-64.so.2` + `libc.so.6`, including the multi-DSO symbol-
versioning + inode-dedup paths that IFUNC/IRELATIV-heavy glibc needs. Chromium
is "just" a much bigger glibc-dynamic program.

So the gap list has three tiers, in dependency order:

| Tier | Gap | Status (MEASURED) | Notes |
|------|-----|--------|------|
| **0. Staging** | Get the 262 MB payload onto the FS | ✅ **SOLVED** | RAM-backed initrd (host 125 GB; ramfs serves the Limine module in-place, zero-copy). Boots `-m 4096`. No tobyfs-populator needed. |
| **1. Shared libraries (DSO)** | chrome `NEEDED`s 28 `.so`s + transitive closure ≈ 60 | ✅ **SOLVED** | Assembled a 122-`.so` sysroot; chrome now loads **every** library. |
| **2. Syscalls** | Chromium's syscall surface vs Track B | ✅ **NO GAP** | **Zero** `[linux] UNHANDLED` syscalls through chrome startup. Track B is already sufficient. |
| **3. CPU/ABI trap delivery** | user-mode `int3` (Chromium `IMMEDIATE_CRASH`/`CHECK`) → `#GP` because `IDT[3]` is DPL 0 | ⛔ **THE WALL** | Small fix: `IDT[3]`/`[4]` DPL 3 + route `#BP`→`SIGTRAP` (reuse B15 `signal_deliver_fault`). |
| **4. Multi-process** | zygote + renderer/gpu/utility | ➖ **collapsed** | `--single-process --no-zygote --no-sandbox` for bring-up. |

## Methodology (instrument-first)

The permanent instrument is the Linux-syscall gap logger in
`src/syscall.c` (`linux_syscall()` default case). This session enhanced it:

- **Named** — `lx_scname()` maps the common x86-64 numbers to names so the log
  reads without a syscall table to hand.
- **Full args + comm** — logs all 5 dispatched args + the process name.
- **First-hit dedup** — a 512-entry seen/hit table prints ONE detailed line per
  unique unimplemented syscall (Chromium spins on epoll/futex variants; the old
  logger would flood the slow serial line). Hot loops re-announce every 100000
  hits so they stay visible.
- **`-DLINUX_SYSCALL_TRACE`** — optional firehose logging *every* Linux syscall
  entry (number+name+args+comm), off by default, kept in-tree like `-DDL_TRACE`.

The gap list is generated by: run chrome → `grep -aE '\[linux\] UNHANDLED|cannot
open shared|error while loading'` the serial log. That grep IS the gap list.

## First boot — the pipeline is proven, the DSO wall is empirical

Real chrome-headless-shell executed on tobyOS. The clean serial log:

```
[235 ms]  [initrd] using '/boot/initrd.tar' (size=361789440 ...)   # 362 MB initrd, Limine module
[392 ms]  [boot] mounted /data on disk 'ide0:master' (existing tobyfs)
[1171 ms] [boot] CHROMIUM: spawning REAL headless Chromium ...
[1438 ms] [proc] pid 2 'chrome' -> Linux ABI personality
          (EI_OSABI=3 interp=/lib64/ld-linux-x86-64.so.2 gnu_phdr=1)   # loaded + auto-detected
chrome-headless-shell: error while loading shared libraries:
          libpthread.so.0: cannot open shared object file             # <-- first gap (DSO tier)
[1641 ms] [boot] CHROMIUM: chrome (pid=2) exit=127
[2956 ms] [hb] #1 up=2s mem=3500/5120MiB free gui=on                   # healthy, 0 faults
```

**What this proves:**
- Staging works — a 362 MB RAM-backed initrd loads and ramfs serves it in-place;
  `-m 4096` boots (3.5 GB free); `/data` is writable.
- Chromium is loaded and correctly classified as a Linux binary; its interp
  `/lib64/ld-linux-x86-64.so.2` resolves; **ld.so runs to completion.**
- **Zero `[linux] UNHANDLED` syscalls before the wall** — every syscall ld.so
  makes (openat/mmap/mprotect/read/pread64/…) is already covered by Track B.
  The only thing between here and `main()` is the missing DSO closure.
- First missing library, measured (not guessed): **`libpthread.so.0`** — a glibc
  2.34+ stub; the sysroot script + the `.glibc-tc` stubs supply it.

## Sysroot-complete boot — the DSO wall falls, chrome runs real code

With the 122-`.so` sysroot staged (`programs/chromium/sysroot.sh` +
`.glibc-tc` glibc runtime, on `LD_LIBRARY_PATH=/opt/chrome/sysroot`), chrome
loads **every** library — no more "cannot open shared object" — ld.so finishes,
and chrome executes its own code for ~4 s before faulting:

```
[1438 ms] [proc] created pid=2 'chrome' entry=0x4001d1c0 argc=12 envc=5
*** EXCEPTION 13: General Protection  (in user mode) ***
[5054 ms]   rip=0x0000000007a63930  cs=0x23  rflags=0x10246
[5054 ms]   rsp=0x00007ffffffff970  ss=0x1b  err=0x1a
[5056 ms]   cr2=0x0  cr3=0xa6c000  cr0=0x80010013  cr4=0x300620
[5126 ms] chrome (pid=2) exit=-1
```

### Tier 2 — the syscall gap list: **EMPTY** (the big surprise)

**Zero `[linux] UNHANDLED syscall` lines.** Chromium's entire startup — ld.so,
glibc init, the thread pool, ICU/V8 bring-up up to the fault — makes **no**
syscall that Track B doesn't already implement. The remaining work is **not**
syscall whack-a-mole. This is the single most important scoping result of M0.

### Tier 3 — the real wall: user-mode `int3` → `#GP` (an ABI trap-delivery gap)

The `#GP` error code **`err=0x1a`** decodes as a selector error referencing
**IDT descriptor 3** (bit1 `IDT`=1, index=3): the CPU tried to vector through
`IDT[3]` (`#BP`) from user mode and the **DPL check failed**. `src/idt.c`
`idt_init()` wires *all 256 vectors* as `0x8E` = present, **DPL 0**, interrupt
gate — so a user-mode `int3` (opcode `0xCC`) raises `#GP` instead of `#BP`.

Chromium's `IMMEDIATE_CRASH()` / `CHECK` / `DCHECK` / `NOTREACHED` macros emit
`asm("int3")` as their trap. So chrome hit an early self-check and its trap
instruction is mishandled by the ABI. **This is the current execution wall, and
it is a small, well-scoped ABI fix, not an open-ended surface:**

- Set `IDT[3]` (`#BP`) and `IDT[4]` (`#OF`) to **DPL 3** (`0xEE`) so user
  `int3`/`into` trap instead of `#GP`.
- Route vector 3 → **`SIGTRAP`** in `isr.c` `default_exception`, reusing the
  existing B15 `signal_deliver_fault()` synchronous-fault→signal path
  (`#GP`→SIGSEGV, `#UD`→SIGILL are already wired there).

Once `int3` delivers `SIGTRAP`, chrome's own SIGTRAP/crash handler runs and
should print *why* it `CHECK`-failed — the next measured gap (M1).

**Net M0 scope answer:** staging solved; DSO closure solved (bounded sysroot);
syscall surface already sufficient (0 gaps); one small ABI trap-delivery gap
(`int3`→`SIGTRAP`) stands between here and chrome's first self-reported error.
Far smaller than the roadmap feared.

## The walls (documented, not chased in M0)

- **Sandbox** → run `--no-sandbox`. Real seccomp-bpf/userns sandbox is a large
  optional sub-project. Caveat: `--no-sandbox` runs untrusted web JS at full
  process privilege — fine for bring-up, unsafe for hostile browsing.
- **Graphics** → headless + bundled SwiftShader; no GPU driver for M0–M2.
  Windowed (M3) needs an Ozone/TobyTK backend later.
- **W^X / futex / threads** → load-bearing for V8's JIT and Chromium's thread
  pool. Track B has clone/clone3/futex/mprotect(PROT_EXEC); verify under
  contention as chrome exercises them.
- **Widevine/DRM** → non-goal (closed source). Clear Key only.

## Burn-down / next (M1)

The burn-down is dramatically ahead of the roadmap. Tiers 0/1/2 are done; the
next single step is small:

1. **`int3` → `SIGTRAP` (Tier 3)** — the one measured wall. `src/idt.c`: set
   `IDT[3]`/`IDT[4]` to DPL 3; `src/isr.c`: map vector 3 → `SIGTRAP` via the
   existing `signal_deliver_fault()`. Then re-run and read chrome's own
   `CHECK`-failure message (the next gap, whatever it is).
2. Iterate the instrument-first loop on whatever chrome self-reports next
   (likely a few small syscalls/behaviours, since Tier 2 is empty so far), until
   chrome `--dump-dom` emits `<h1>tobyOS</h1>` → **M1 done**.
3. Then `--screenshot` a static page and diff vs host chrome (same engine ⇒
   near-pixel; a large diff = an ABI bug, not a render gap).
